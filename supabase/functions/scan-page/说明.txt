scan-page Edge Function 所需环境变量（在 Supabase 控制台 Functions → Secrets 中配置）：

【默认配置：火山方舟 · 豆包 Seed 2.1 Lite】
代码默认值已设为国内可直接使用的豆包模型，服务端 Secrets 已配置好：
  1. ARK_API_KEY   （必填）火山方舟的 API Key —— 已配置
                    代码也兼容 OPENAI_API_KEY / VOLC_API_KEY 变量名
  2. AI_BASE_URL   （可选）默认 https://ark.cn-beijing.volces.com/api/v3
  3. AI_MODEL      （可选）默认 doubao-seed-2-1-lite-260915（带版本后缀）—— 已配置
                    这是实测该账号已开通、支持"图片输入+json_object"的模型；
                    Turbo/Pro 未开通会报 ModelNotOpen。换模型需先在方舟控制台开通，
                    可用模型 ID 可在 https://ark.cn-beijing.volces.com/api/v3/models 查询。
                    已关闭思维链(thinking disabled)以省 token、提速。

【改用其他模型】
  - 通义千问 Qwen-VL：
      supabase secrets set AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
      supabase secrets set AI_MODEL=qwen-vl-max
      supabase secrets set OPENAI_API_KEY=sk-xxxx        （阿里云百炼的 key）
  - OpenAI：
      supabase secrets set AI_BASE_URL=https://api.openai.com/v1
      supabase secrets set AI_MODEL=gpt-4o
      supabase secrets set OPENAI_API_KEY=sk-xxxx

【自动注入，无需手动配置】
  4. SUPABASE_URL     项目 URL
  5. SUPABASE_SERVICE_ROLE_KEY  service_role 密钥

【部署命令】
  supabase login
  supabase link --project-ref <你的项目 ref>
  supabase secrets set ARK_API_KEY=你的方舟密钥
  supabase functions deploy scan-page
  # 若提示需 JWT 验证且用 anon key 调用失败：
  # supabase functions deploy scan-page --no-verify-jwt

【JSON 兼容性说明】
代码会先带 response_format=json_object 请求以强制输出纯 JSON；
豆包等模型若报"参数不支持"，会自动去掉该参数重试（提示词已要求只输出 JSON）。
因此豆包、通义、OpenAI 均可开箱即用。

【跨页合并接口说明】
请求体 JSON：
  imageUrl       （必填）图片公开 URL
  bookId         书名 ID，默认 victor；必须已在 vw_books 表中存在（有外键约束）
  pageNo         页码
  batchId        扫描批次 ID（可选）
  prevContext    上一页页尾上下文（可选）：{word, note, senses:[...]}
                 传入后注入提示词，帮助 AI 判断本页开头承接哪个词，避免跨页断裂

响应体新增字段：
  boundary       {head:{word,note}, tail:{word,note}} 页首承接词 / 页尾延续词
  nextContext    传给下一页的上下文（页尾词 + 义项 + 例句），前端应原样传给下一页的 prevContext
  merged_senses  本次命中并合并的已有义项数
  merged_examples 本次因重复而跳过插入的例句数

入库为合并式（非覆盖）：按 headword+词性+义词编号匹配义项，按英文文本归一化去重例句，
因此同一单词跨页重复出现时不会翻倍。前端应采用"顺序逐页调用、逐页传递 nextContext"的方式批量处理。

注意：
- service_role 密钥与 AI Key 只在服务端使用，绝不能写入前端或暴露在浏览器。
- 单张图片建议 < 10M，过大的扫描图请先压缩。
